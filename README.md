# SubHub · 子账号门户

一个纯静态的「主账号托管子账号」门户站。所有仓库实际都存在于**一个主账号**下，站点按仓库名前缀把仓库归属到各自的子账号，并以 `子:<用户名>:` 标签展示。

- 无后端、无数据库、无第三方服务器：前端直接调用 GitHub REST API
- 令牌只保存在使用者本机浏览器（localStorage），换设备时重新输入即可
- 可托管在 GitHub Pages，零成本运行

## 一、命名规则（重要）

GitHub 只允许仓库名包含 ASCII 的字母、数字、`.`、`-`、`_`，**中文、`#`、`:` 都不合法**，所以标签与真实仓库名分开：

| 项 | 形式 | 示例 |
|---|---|---|
| 界面标签 | `子:<用户名>:` | `子:alice:` |
| 真实仓库名 | `sub-<用户名>--<仓库名>` | `sub-alice--demo` |

站点会自动加前缀，子账号在界面上只需要填仓库短名。

## 二、子账号生命周期

1. **主账号登录**：用户名填 `mi-2849`，令牌填主账号 PAT → 获得「注册子账号」入口
2. **登记子账号**：填写用户名（小写字母/数字/连字符，2~29 位）+ 该子账号使用的令牌
   - 首次登记会自动创建私有索引仓库 `subaccounts`，写入 `accounts.json`
   - 记录内容：用户名、令牌、令牌指纹（SHA-256 前 16 位）、登记时间
3. **子账号登录**：任意设备打开站点，输入 用户名 + 令牌 → 进入该子账号的仓库列表
4. **新建仓库**：子账号在站内创建的仓库，实际落在主账号下，名字自动带 `sub-<用户名>--` 前缀

## 三、部署到 GitHub Pages

1. 把本目录内容推到一个**公开**仓库（免费版 Pages 只支持公开仓库），例如 `subportal`
2. 仓库 Settings → Pages → Source 选 `Deploy from a branch`，分支 `main` / 目录 `/ (root)`
3. 等 1 分钟左右，访问 `https://<主账号>.github.io/subportal/`

> 页面公开可访问没关系，没有令牌进不去；索引仓库 `subaccounts` 必须保持私有。

## 四、令牌需要什么权限

| 令牌类型 | 所需权限 |
|---|---|
| Classic PAT | `repo`（读写私有仓库、创建仓库） |
| Fine-grained PAT | Repository access 选主账号全部仓库；Permissions 需 `Administration: Read and write`（创建仓库）、`Contents: Read and write`（读写文件） |

主账号令牌权限较宽，建议只在主账号登录时使用，用完及时在浏览器退出。

## 五、安全须知

- 子账号令牌按当前设计**明文存放**在私有仓库 `subaccounts` 的 `accounts.json` 里。
  - 私有仓库默认不触发 GitHub secret scanning，但**任何能读到该仓库的人都能拿到全部子账号令牌**；
  - 一旦该仓库被改为公开、或索引文件被导出，令牌可能被 GitHub 检测并**自动吊销**；
  - 建议给每个子账号使用独立的 fine-grained 令牌，并按最小权限勾选，便于单独吊销。
- 站点运行在浏览器里，令牌会出现在浏览器的 localStorage 中，公用电脑上用完请点「退出」。
- `子账号` 与 `主账号` 共用同一个 GitHub 账号，若这些账号分属不同的人，请注意 GitHub 服务条款对账号共享的限制。

## 六、目录结构

```
subportal/
├── index.html     # 页面骨架（登录视图 + 主视图）
├── styles.css     # GitHub 风格样式，自动适配深/浅色
├── app.js         # 全部逻辑：登录、索引读写、仓库列表、新建仓库、子账号登记
├── .nojekyll      # 关闭 Jekyll 处理
└── README.md
```

## 七、已知边界

- 前缀只做**视图隔离**，不是权限隔离：所有子账号的仓库物理上都属于主账号，持主账号令牌即可看到全部。若需要真正的权限隔离，得为每个子账号签发限定到对应仓库的 fine-grained 令牌。
- 站点不提供删除仓库、改可见性等破坏性操作，需要的走 GitHub 网页或独立确认流程。
- 索引文件由前端直接 PUT 更新，存在并发写入覆盖的可能（多人同时登记时）。单人或低频使用无影响。

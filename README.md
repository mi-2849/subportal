# SubHub · 主账号托管的子账号门户

一个**纯静态**的子账号门户站：托管在 GitHub Pages 上，没有服务器、没有数据库，
所有数据都通过浏览器直连 GitHub REST API，读写**你自己的私有仓库**。

在线地址：<https://mi-2849.github.io/subportal/>

---

## 一、它解决什么问题

用一个主账号（`mi-2849`）当"总管理"，给一批子账号各自开一块仓库空间：

- **物理隔离**：子账号的仓库统一叫 `sub-<用户名>--<仓库名>`（ASCII 名，GitHub 允许）
- **界面标签**：站点上渲染成 `子:<用户名>:`，一眼看出归属
- **账号密码**：主账号首次登录时设置主密码，之后每次登录都要输；子账号同理
- **加密存储**：令牌等敏感内容用 AES-256-GCM 加密后再写进主账号的私有仓库 `subaccounts`

---

## 二、登录流程（三步，主子账号一致）

```
第 1 步  令牌 PAT        → 调 /user 校验这枚令牌是否有效，同时显示它属于哪个 GitHub 账号
第 2 步  密码            → 主账号：用来派生解密密钥；子账号：用来比对密码哈希
第 3 步  用户名          → 决定"你是谁"：主账号名，还是某个已登记的子账号
```

结果分支：

| 情况 | 结果 |
| --- | --- |
| 用户名 = `mi-2849`，且**加密库还没建** | 进入**设置主密码**界面，设完即建立加密库并进入 |
| 用户名 = `mi-2849`，加密库已存在但密码错 | 拒绝进入（AES-GCM 认证失败 = 密码不对） |
| 用户名 = `mi-2849`，但令牌不属于主账号 | 拒绝进入 |
| 用户名 = 已登记子账号，未设过密码 | 进入**设置密码**界面 |
| 用户名 = 已登记子账号，密码错 | 拒绝进入 |
| 用户名 不在索引里 | 拒绝进入（提示让主账号先登记） |

> 密码**不是** GitHub 密码，是本站在你首次登录时让你自设的一个密码。

## 三、加密怎么做的

### 3.1 两个不同的密码

| 角色 | 密码的用途 | 存法 |
| --- | --- | --- |
| 主账号 | ① 身份校验 ② **派生 AES 密钥解密 vault** | 不存；密钥由密码 + 盐现场派生，密文解不开就是密码错 |
| 子账号 | 仅身份校验 | 存 `PBKDF2-SHA256` 哈希（盐 16 字节、迭代 150000 次） |

### 3.2 vault（加密块）

敏感内容（**各账号令牌表**）序列化成 JSON 后整体加密：

```
主密码 --PBKDF2-SHA256(150k, 随机16字节盐)--> 256 位密钥
密钥 --AES-256-GCM(随机12字节IV)--> { iv, ct }
```

- 写入仓库的只有 `iv` / `ct` / 盐 / 迭代次数，**没有明文令牌**
- AES-GCM 自带完整性校验：密码不对 → 解密直接抛错，不需要额外的"密码对不对"字段
- 主账号登录成功后，密钥只留在浏览器内存里，**不写 localStorage**，退出即丢弃

### 3.3 忘记主密码的后果

vault 无法解密，**里面的令牌永久无法恢复**。站点不提供"找回"，只能在 GitHub 上删掉
`accounts.json` 重新建库（子账号仓库不受影响，重新登记令牌即可）。

## 四、数据存在哪

私有仓库 **`mi-2849/subaccounts`** → `accounts.json`（v3）

```json
{
  "version": 3,
  "main_account": "mi-2849",
  "prefix": "sub-",
  "sep": "--",
  "cipher": "AES-256-GCM",
  "updated_at": "2026-09-16T00:00:00.000Z",
  "vault": {
    "algo": "AES-256-GCM",
    "kdf": { "algo": "PBKDF2-SHA256", "iter": 150000, "salt": "…", "hash": "SHA-256", "bits": 256 },
    "iv": "…",
    "ct": "…",
    "updated_at": "…"
  },
  "accounts": [
    { "username": "mi-2849", "role": "main", "created_at": "…", "updated_at": "…" },
    { "username": "alice", "role": "sub", "password": { "algo": "…", "iter": 150000, "salt": "…", "hash": "…" }, "created_at": "…", "updated_at": "…" }
  ]
}
```

**明文可见的只有**：用户名、角色、时间戳、子账号密码哈希（不可逆）。
**密文里躺着**：所有账号的令牌 —— `{ "tokens": { "mi-2849": "ghp_…", "alice": "ghp_…" } }`

- 仓库不存在时首次写入**自动创建**（私有，`auto_init`）
- 每次写入带 `sha`，等价于乐观锁，避免覆盖别人的改动
- 子账号首次自设密码时**不动 vault**，只追加自己的密码哈希，因此子账号无需主密码

## 五、功能一览

**子账号**
- 看自己的仓库列表（按 `sub-<用户名>--` 前缀过滤）
- 新建仓库（自动补前缀，可选公开 / 私有）
- 进仓库看详情：描述、Star/Fork/Issue、根目录文件、README
- 首次登录自设密码

**主账号**（额外）
- 「注册子账号」：填用户名 + 该子账号令牌 + 可选初始密码；令牌即时加密进 vault
- 「重置子账号密码」
- 「已登记账号」表格：角色、标签、密码状态、**令牌（打码显示，如 `ghp_…9f2c`）**、仓库前缀、更新时间
- 表尾显示当前 vault 算法、迭代次数与最后写入时间

## 七、要改配置改哪里

`app.js` 顶部的 `CFG`：

```js
const CFG = {
  main: "mi-2849",            // 主账号用户名
  prefix: "sub-",             // 仓库名前缀
  sep: "--",                  // 前缀与仓库名分隔符
  indexRepo: "subaccounts",   // 索引仓库名（私有）
  indexPath: "accounts.json", // 索引文件
  cipher: "AES-256-GCM",      // 加密算法
  kdf: { algo: "PBKDF2-SHA256", iter: 150000, bits: 256 },
  minPassword: 6,             // 密码最短长度
};
```

> 想换更强的参数：只改 `iter` 即可。旧数据自带迭代次数，能继续解开；
> 但**主密码本身不可"重加密"** —— 改完之后新建的库才用新参数。

## 八、注意事项

1. 令牌、密码、解密密钥都只在浏览器内存里，**不写 localStorage**；刷新页面即清空
2. 必须在 **https** 下访问（Pages 默认就是），否则浏览器不提供 `crypto.subtle`
3. 加密保护的是"**静态存储**"：仓库文件被人看到也读不出令牌；但它挡不住拿到主密码的人
4. 仓库可见性务必保持 **私有**。改为公开只会泄露账号名单与密码哈希（令牌仍然安全，但没必要）
5. 子账号令牌建议用 **fine-grained PAT**，只勾选对应仓库的读写权限，别发 classic 全权限令牌
6. 主账号那枚 classic 令牌权限很宽（含 `delete_repo`、`admin:org` 等），建议尽早轮换成 fine-grained 并只给本仓库所需权限

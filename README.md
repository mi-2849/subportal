# SubHub · 主账号托管的子账号门户

一个**纯静态**的子账号门户站：托管在 GitHub Pages 上，没有服务器、没有数据库，
所有数据都通过浏览器直连 GitHub REST API，读写**你自己的私有仓库**。

在线地址：<https://mi-2849.github.io/subportal/>

---

## 一、它解决什么问题

用一个主账号（`mi-2849`）当"总管理"，给一批子账号各自开一块仓库空间：

- **物理隔离**：子账号的仓库统一叫 `sub-<用户名>--<仓库名>`（ASCII 名，GitHub 允许）
- **界面标签**：站点上渲染成 `子:<用户名>:`，一眼看出归属
- **账号密码**：主账号首次登录时设置密码，之后每次登录都要输；子账号同理
- **单一存储**：密码（哈希）和账号信息全部存在主账号的一个**私有仓库** `subaccounts/accounts.json` 里

## 二、登录流程（三步，主子账号一致）

```
第 1 步  令牌 PAT        → 调 /user 校验这枚令牌是否有效，同时显示它属于哪个 GitHub 账号
第 2 步  密码            → 仅暂存在内存，用来和记录里的哈希比对
第 3 步  用户名          → 决定"你是谁"：主账号名，还是某个已登记的子账号
```

三种结果：

| 情况 | 结果 |
| --- | --- |
| 用户名 = `mi-2849`，且令牌确实属于主账号 | 主账号身份进入，多出「注册子账号」入口 |
| 用户名 = `mi-2849`，但**还没设过密码** | 进入**设置密码**界面，设完即进入 |
| 用户名 = 已登记的子账号，未设过密码 | 进入**设置密码**界面 |
| 用户名 = 已登记的子账号，已设过密码但输错 | 拒绝进入 |
| 用户名 不在索引里 | 拒绝进入（提示让主账号先登记） |
| 用户名 = `mi-2849`，但令牌不属于主账号 | 拒绝进入 |

> 密码**不是** GitHub 密码，是本站在你首次登录时让你自设的一个密码。

## 三、密码怎么存

- 算法：`PBKDF2-SHA256`，随机 16 字节盐，迭代 150000 次，输出 256 位
- 落库内容：`{ algo, iter, salt, hash, updated_at }`，**只存哈希，不存明文**
- 校验：都用同一套派生流程算出结果再做定长比较
- 忘记密码：由主账号在「注册子账号」面板里重置

## 四、数据存在哪

私有仓库 **`mi-2849/subaccounts`** → `accounts.json`

```json
{
  "version": 2,
  "main_account": "mi-2849",
  "prefix": "sub-",
  "sep": "--",
  "updated_at": "2026-09-16T00:00:00.000Z",
  "accounts": [
    {
      "username": "mi-2849",
      "role": "main",
      "token": "ghp_xxx",
      "token_fp": "9f2c1a...",
      "password": { "algo": "PBKDF2-SHA256", "iter": 150000, "salt": "...", "hash": "...", "updated_at": "..." },
      "created_at": "...",
      "updated_at": "..."
    },
    {
      "username": "alice",
      "role": "sub",
      "token": "ghp_yyy",
      "token_fp": "...",
      "password": null,
      "created_at": "...",
      "updated_at": "..."
    }
  ]
}
```

- 仓库不存在时，**首次登记账号会自动创建**（私有，`auto_init`）
- 每次写入都带 `sha`，等价于乐观锁，避免覆盖别人的改动

> ⚠️ 子账号令牌按既定选择**以文本形式**存在这个私有仓库里。
> 谁能读到这个仓库，谁就拿到了所有子账号的令牌 —— **绝对不要把它改成公开仓库**。

## 五、功能一览

**子账号**
- 看自己的仓库列表（按 `sub-<用户名>--` 前缀过滤）
- 新建仓库（自动补前缀，可选公开 / 私有）
- 进仓库看详情：描述、Star/Fork/Issue、根目录文件、README

**主账号**（额外）
- 「注册子账号」：填用户名 + 该子账号的令牌，可顺便设初始密码（留空则子账号首次登录自设）
- 「重置子账号密码」
- 「已登记账号」表格：角色、标签、密码是否已设置、仓库前缀、更新时间

## 七、要改配置改哪里

`app.js` 顶部的 `CFG`：

```js
const CFG = {
  main: "mi-2849",            // 主账号用户名
  prefix: "sub-",             // 仓库名前缀
  sep: "--",                  // 前缀与仓库名分隔符
  indexRepo: "subaccounts",   // 索引仓库名（私有）
  indexPath: "accounts.json", // 索引文件
  kdf: { iter: 150000 },      // 密码派生迭代次数
  minPassword: 6,             // 密码最短长度
};
```

## 八、注意事项

1. 令牌始终只在浏览器内存里，每次登录都要重填，**不写 localStorage**
2. 密码长度至少 6 位；哈希参数写在 `accounts.json` 里，将来调迭代次数不会让旧密码失效
3. 必须在 **https** 下访问（Pages 默认就是），否则浏览器不提供 `crypto.subtle`
4. 当前权限模型是"软隔离"：仓库靠前缀划分，令牌本身仍是各自的 PAT，能做什么取决于令牌的权限范围
5. 建议给子账号用 **fine-grained PAT**，只授予对应仓库的读写权限，不要发 classic 全权限令牌
